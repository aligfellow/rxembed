# XYZ-path metal perception: rxembed vs OIN — 10 divergent structures

Generated by a diagnostic run on `oin-unification` @ `ce59f34`, xyzgraph **1.6.12** (PyPI, resolved by
`uv sync`; the editable clone at `/home/ali/Documents/Codes/xyzgraph` is 1.6.13 — see caveat below).
Corpus: `OIN-SMILES/tests/integration/tmQM/*.xyz` + `tests/fixtures/*.xyz` (144 files, 141 OIN-perceivable).

## Measured corpus result

**12 of 141** structures have a different metal donor set; **9** of those change polytope.
(The mapping run's "11 of 141 / 8 polytope-changed" reproduces — the extra row is `WACJET`, where
rxembed's perception *raises* rather than differing.) `MOCHUH` and `AGUFEN` differ in donors but land
on the same polytope.

## Read this first — the two MAE columns are NOT comparable

`rx MAE` is near-zero everywhere (0.001–0.009 Å) **by construction**: `metal.from_geometry` seeds the
embed with the crystal's own realised M–donor distances, so the embed reproduces whatever it perceived,
phantoms included. `oin MAE` (0.023–0.121 Å) is a genuine 1D→3D round-trip (`mol_to_cxsmiles` →
`embed_cxsmiles`). **MAE does not discriminate here.** The discriminating column is `sphere Δ` — what
the coordination sphere of the *embedded* geometry contains when re-perceived independently.

## What to look at first

1. **ROLWAR** — the clearest single bug. Open `ROLWAR_crystal.xyz` and `ROLWAR_rxembed.xyz` side by
   side: the two AsPh₃ ligands are still *present* in the rxembed geometry but are no longer bonded to
   Pd, so the complex is modelled as linear Br–Pd–Br with two free arsines. Root cause is **not** a
   threshold: Pd–As is 2.350 Å and xyzgraph's distance cutoff is 0.65 × (vdw_Pd + vdw_As) = **2.827 Å**,
   which the bond passes. It is killed afterwards by an **element allowlist** —
   `xyzgraph/src/xyzgraph/bond_detection.py:124-144` (`_should_bond_metal`) permits
   `O N C P S H` / `F Cl Br I` / `B Si Se Te` and returns `False` for everything else. **As, Ge, Sb, Bi,
   and Te's neighbours are simply absent from the list.** Same mechanism for ZONHOB (Ru–B *is* allowed,
   so that one is a threshold miss at 2.690 Å) and WELROW (La–P at 3.311 Å is a genuine threshold miss).

2. **ZOPJOG** — how 10 donors become 4 vertices. The two catecholate ligands each contribute the two
   phenolate O **and** the two ring carbons that bridge them:
   `C4` (O1 1.343, C5 1.419, C11 1.397) at 2.567 Å from Ti, `C5` (O2 1.343) at 2.577 Å.
   xyzgraph bonds both to Ti because 0.65 × (vdw_Ti + vdw_C) = **2.937 Å**. `metal._haptic_sites`
   (`constraints/metal.py:446`) then flood-fills over *donor–donor ligand bonds*: O1–C4–C5–O2 are a
   connected chain within the donor set, so the whole `(1,2,4,5)` group becomes **one** haptic face →
   one centroid vertex. Same for `(61,62,63,64)`. The NCCN's N3 and N49 stay separate. Result:
   4 vertices → `square_planar` (the reported "tetrahedral" is the same 4-vertex collapse; `geometry_for`
   returns `square_planar` at this commit, `tetrahedral` when the apical test fires). **The phantom C are
   load-bearing**: without them O1 and O2 are not bonded to each other, so each is its own vertex →
   6 vertices → octahedral, which is correct.

3. **GODNOD** — identical mechanism, tighter. Ni is 2.464/2.465 Å from `C0`/`C1`, which are the *central
   carbons of two dithiocarbamate-type chelates*: `C0` is bonded to `N94` (1.324), `N92` (1.330) and
   `S104` (1.714). It sits near Ni because it is the apex of a 4-membered bite, not because it donates.
   Cutoff 0.65 × (vdw_Ni + vdw_C) = **2.773 Å**, so it bonds. The donor set `(C0,N92,S104)` is then
   mutually bonded → one face; `(C1,N93,S105)` → one face. **6 donors → 2 vertices → linear.** Drop the
   two carbons and it is N,S / N,S = 4 donors, no face at all (N and S are not bonded to each other),
   → square planar. The owner is right; the fix is upstream of the collapse.

4. **AGUFEN** — the one where the *donors are real and the model is wrong.* The three P at 2.781/2.782/
   2.787 Å each carry two C and one N (P–N 1.672–1.679 Å); the N are at 2.260/2.277/2.286 Å. These are
   three genuine **κ²-N,P phosphinoamides** on Y — Y–P at 2.78 Å is below the covalent-radius sum
   (1.90 + 1.07 = 2.97 Å) and is a real dative interaction. **OIN is the one losing information here**:
   its asymmetry cut (`xyz2mol.py:1133-1152`, |Δd| ≥ 0.4 Å) drops all three P because
   |2.782 − 2.277| = **0.505 Å**, and it reads a bare 3-coordinate N₃Y. So do *not* port rule (a).
   rxembed's error is different and narrower: `_regular_face` (`constraints/metal.py:471`) declares the
   N–P edge a rigid face because **every atom has the same face-degree (1)** — a purely graph-topological
   test that is *element-blind*. It then pins both N and P to one centroid at one shared radius, which
   forces d(Y,N) = d(Y,P). Measured over the whole corpus:

   | regular faces | n | mean d-spread | max |
   |---|---|---|---|
   | homonuclear (C=C, Cp, arene) | 47 | **0.126 Å** | 0.448 |
   | heteronuclear (N–P, …) | 7 | **0.262 Å** | 0.521 |

   AGUFEN's three N,P edges are the three largest-spread regular faces in the corpus. A homonuclear edge
   really is equidistant from its midpoint; a heteronuclear one is not. The face rule needs a
   **distance-symmetry** gate alongside the degree-regularity gate, not an element blacklist.

## Answers to the three open questions

**Q1 — missing filter, threshold, or version?** All three, in different structures; the mapping run's
single framing is wrong.
- *Element allowlist bug* (ROLWAR): `_should_bond_metal` has no `As`. Not a threshold, not a filter.
- *Threshold too permissive for M–C* (GODNOD, ZOPJOG, SIFJUO, NUDXOC, WAVBUS): `threshold_metal_ligand
  = 0.65` puts the M–C cutoff at 2.77–2.94 Å, which sweeps in chelate-backbone carbons at 2.36–2.58 Å.
  A real M–C σ bond is 1.8–2.2 Å; the margin is large, so this is genuinely over-permissive for C
  specifically — but lowering it globally would break η⁵-Cp (2.05–2.63 Å in this corpus), so it cannot
  be a scalar change.
- *Threshold too tight* (SIKQIO Mo–C 2.394, WELROW La–P 3.311, ZONHOB Ru–B 2.690): the same 0.65 is too
  small for these. So there is no single scalar that fixes the set.
- *Version*: the resolved xyzgraph is **1.6.12** from PyPI, not the 1.6.13 clone. I did not re-run
  against 1.6.13, so a small shift is possible; the `_should_bond_metal` allowlist is present in the
  clone's source too, so ROLWAR is unaffected by the version question.

**Q2 — XYZ path only?** **Confirmed.** From SMILES the donor set is exactly what is written:
`[Br][Pd]([Br])([AsH3])[AsH3]` and `Br[Pd](Br)(<-[AsH3])<-[AsH3]` both give 4 donors (Br,Br,As,As →
square planar), and `c1ccccc1O[Ti]` gives the single O with no ring-carbon phantom. `metal.prepare`
(`constraints/metal.py:406`) reads `GetNeighbors()`, and from SMILES those neighbours are the user's
dative bonds. Every defect above enters through `io._xyz_to_mol` → `xyzgraph.build_graph`.

**Q3 — where does the fix belong?** Split it:
- The **element allowlist** and the **M–C over-permissiveness** are perception defects and belong in
  **xyzgraph** — they are wrong for any consumer, and xyzgraph is the shared layer. Adding `As Ge Sb Bi`
  to `_should_bond_metal` is a one-line, no-downside fix (propose, do not apply — that clone is the
  user's). The M–C case wants a *structural* rule, not a scalar: a carbon bonded to two or more atoms
  that are themselves M-donors is a chelate backbone, not a donor. That is OIN's element rule (b)
  generalised past "aromatic", and it is the right shape for upstream.
- OIN's **asymmetry cut (rule a) should NOT be ported** — AGUFEN shows it deleting three real donors.
  rxembed is *more* correct than OIN there.
- The **face-collapse symmetry gate** belongs in **rxembed** (`_regular_face`), because it is about
  rxembed's centroid embed mechanism, not about what is bonded. xyzgraph has no opinion on η².
- OIN forked perception into `xyz2mol_local.py` because it needed rules (a) and (b) together and (a) is
  not defensible upstream. Since we are rejecting (a), rxembed does **not** need a fork — (b)-generalised
  goes upstream and the η² gate stays local. That is the cleaner split.

## Caveats / gaps

- `WACJET`, `WIMCAA`, `XAQDUS` fail rxembed's perception outright (kekulisation / hypervalent B) and are
  excluded from the 141.
- The `rx MAE` column is not a fidelity measure (see above). A like-for-like number would need rxembed
  embedded from a *coordinate-free* input, which `from_geometry` by definition is not.
- xyzgraph 1.6.13 (the local clone) was not re-measured; all numbers are 1.6.12.
- Whether the M–C threshold should move at all, versus being handled entirely by the chelate-backbone
  rule, is untested here — I only measured that a scalar change cannot satisfy both directions.

## Caveat on the `*_rxembed.xyz` files (added 2026-07-20)

These were generated at `ce59f34` against xyzgraph 1.6.12 — i.e. **before** the cross-link
perception fix (xyzgraph 1.6.14) and before the sites/donors fix in `metal.py`. The donor-set and
polytope columns above are superseded; regenerate before trusting them.

`WELROW_rxembed.xyz` specifically shows three crushed P–Se bonds (1.250 / 1.480 / 2.854 Å against a
crystal 2.15 Å) and two Se driven into carbons at 1.9 Å. **This does not reproduce.** A clone at
`ce59f34` with xyzgraph 1.6.12 — this file's own stated generating configuration — ran 80 conformers
with zero crushed bonds. It came from a code path that no longer exists. Do not re-investigate it.

The `*_crystal.xyz` files are unaffected: they are source geometries, not output.
